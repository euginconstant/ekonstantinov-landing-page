# Код карты в ссылке (СС64)

Короткий формат, в котором посетители heatmap сохраняют и шэрят свою версию
карты: набор посещённых стран/территорий мира и регионов РФ. Кодек —
`heatmap/share-codes.js`, тесты — `tools/heatmap/test-share-codes.mjs`
(`node tools/heatmap/test-share-codes.mjs`).

## Как это работает у пользователя

- **Загрузил GPX/FIT** — результат сразу кодируется в адрес страницы
  (параметры `w1` и `r1`, `history.replaceState`): ссылка = сохранённая карта.
- **Открыл ссылку с кодом** — карта рисуется по коду: полная геометрия
  (`geo/full/*`), без бандла сайта; тогглы «Страны» и «Регионы России»
  включены по умолчанию. База из ссылки — отправная точка: свои треки
  добавляются поверх, сброс возвращает карту из ссылки.
- **«Поделиться ссылкой»** — код текущей карты (бандл + своя часть) в буфер
  обмена. Адресная строка при этом не меняется: обычный просмотр сайта не
  превращается в режим ссылки.

## Формат

Алфавит СС64, индексы 0–63 (это собственная шестибитная кодировка, НЕ
стандартный Base64):

```
0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_~
```

- Один объект — один бит, шесть последовательных объектов — один символ.
  Вес объекта с индексом `i` внутри кластера: `1 << (i % 6)`; значение символа
  — побитовое OR весов отмеченных объектов. Первый объект кластера — младший
  бит **первого** символа (обычное преобразование «число → СС64» не подходит).
- Кластеры кодируются независимо и склеиваются через `-`. Хвостовые символы
  `0` внутри кластера срезаются; пустой кластер — `0`; хвостовые пустые
  кластеры удаляются; полностью пустой набор — `0`.
- При декодировании отсутствующие хвостовые кластеры/символы означают нулевые
  биты, лишние хвостовые нули допускаются (повторное кодирование
  канонизирует строку). Ошибки: неизвестные символы, лишние кластеры,
  превышение длины кластера, ненулевые резервные биты.
- Регистр значим. Статус территории (страна/территория/регион) на алгоритм не
  влияет, каждый объект независим — отметки родителей/соседей не выставляются.

## Справочники

Порядок кластеров, списки и алфавит фиксированы в пределах версии и не
сортируются динамически. Идентификаторы стабильны и отделены от названий.

**Мир, `w1`** — 5 кластеров в порядке Европа-Азия-Африка-Америка-Океания,
всего 205 объектов, максимальные длины кластеров 8/9/10/6/3 символов, максимум
40 символов с разделителями. Идентификаторы — ISO 3166-1 alpha-2 из geo-данных
(`properties.iso`). Для сущностей без кода — пользовательский диапазон XA–XZ
(не пересекается с реальными ISO): `XA` — Абхазия, `XC` — Северный Кипр,
`XN` — Приднестровье, `XO` — Южная Осетия, `XS` — Сомалиленд. Полные списки —
в `WORLD_SCHEME` (`heatmap/share-codes.js`); геометрия есть не для всех
(например, Приднестровья нет в Natural Earth 50m) — такой объект хранится в
коде и считается в статистике, но контуром не рисуется.

**Регионы РФ, `r1`** — 2 кластера Запад-Восток, 85 объектов (58 + 27),
максимальные длины 10/5 символов. Идентификаторы — `properties.code` из
`geo/full/russia-regions.json` (ISO 3166-2:RU), в т.ч. Крым = `UA-43`,
Севастополь = `UA-40`. Россия в мире — объект `RU`, отображается регионами.

## Версионирование

Схема хранится в имени параметра: `w1.<код>` / `r1.<код>` (в URL — `?w1=…&r1=…`).
Списки, порядок кластеров, алфавит и порядок битов неизменны в пределах версии.
Несовместимые изменения = новая версия (`w2`, `r2`) и новый параметр: старые
ссылки продолжают разбираться.

## Контрольные примеры

| Набор | Код |
| --- | --- |
| Мир: пусто | `0` |
| Мир: Россия + Италия + Германия | `B` |
| Мир: Россия + Австралия | `1-0-0-0-1` |
| Мир: Россия + Турция + Тайвань | `1-100000008` |
| РФ: пусто | `0` |
| РФ: Москва + Краснодарский край + Санкт-Петербург | `d` |
| РФ: Москва + Приморский край | `1-1` |
| РФ: Москва + Иркутская обл. | `1-02` |
| РФ: Москва + Чукотский АО | `1-00004` |
